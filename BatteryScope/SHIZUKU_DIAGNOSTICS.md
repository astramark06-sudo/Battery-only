# Optional Shizuku charging diagnostics (candidate 1.16)

Start Shizuku in ADB mode, open BatteryScope tools, tap the Shizuku enable/disable button and approve. Opt-in is process-local. Raw shell inventory entries are separate `@shizuku/` keys in the existing JSON field; normal sensor validation and derived values are unchanged. The fixed user service reads only the existing charging-only allowlist, bounded to 300 fields/3000 entries/1500 ms soft budget. No arbitrary commands, paths, writes, root or app-usage monitoring. Service disconnect/revocation falls back to ordinary telemetry; re-enable manually. ADB SELinux may still deny sensors. No physical Shizuku access test has been performed. New exact permission policy includes the Shizuku API permission; previous five-permission signing kits are for 1.15 only. Use a verified new baseline and owner-controlled key for production.
