# Shizuku charging diagnostics — 1.17 candidate

User evidence: authorized app, two CONNECTING observations in a 12-sample history, no privileged measurements. Confirmed defects in 1.16: no connection timeout or recovery, synchronous privileged snapshot inside the ordinary inventory worker, connection success not validated, stale callbacks/read results possible, no server-death handling or exported transport timing. Root cause of the missing callback remains unconfirmed.

Official API 13.1.5 UserService remains preferred (non-daemon, fixed read-only service, bumped service version, explicit ADB shell UID check). The API guide: https://github.com/RikkaApps/Shizuku-API#userservice . OEM UserService startup issue documented at https://github.com/RikkaApps/Shizuku/issues/1198 . A missing callback is NOT proof of this specific OEM bug. After a 35-second connection timeout or failed/timed-out read, API 13 only has an optional compatibility transport using the deprecated private newProcess method (https://github.com/RikkaApps/Shizuku-API/issues/211); it invokes one fixed read-only battery dump and exact charging sysfs path allowlist, never takes commands/paths from a user, and may be unavailable on future Shizuku versions. No root, no device settings modification, no arbitrary command facility, no permission bypass. Bound output and external timeout, one task per transport, no unlimited threads or retries. Android APIs and ordinary inventory stay independent. Record source, read time, server identity, result availability; reject stale generation/age and ignore late callbacks. Distinguish transport connection from readable sensors. Disable on recorder stop; server death requires manual re-enable. User authorization is process-local. Actual ADB access remains device/SELinux dependent; no inferred units, wattage or calibration. Version 1.17/code 18, six permissions unchanged, no schema change. Old key remains unavailable; no production release authorized.

Acceptance: test ordinary recording without Shizuku, authorized server startup/timeout, successful primary and fallback raw results, permission revocation/server death, retry/disable, bounded reply/age, export/restore, and actual handset sensor values. CI emulator does not supply a real Shizuku server.
